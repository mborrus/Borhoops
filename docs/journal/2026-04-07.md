## HPC Model Candidates

### 1. Bayesian Hierarchical (PyMC) — BEST FIT FOR HPC
- Natural hierarchy: Conference → Team → Game
- MCMC sampling is embarrassingly parallel (168 CPUs = 168 chains)
- Outputs full posteriors → calibrated probabilities (exactly what Brier score rewards)
- CPU-native, no GPUs needed

### 2. Deep Feed-Forward ANN (PyTorch)
- Needs 30+ features to justify depth over XGBoost
- HPC: parallel hyperparameter search across nodes
- Risk: tabular data often doesn't benefit much from depth

### 3. Temporal Model (LSTM or 1D-CNN)
- Represent each team's season as sequence of per-game stats
- Input: (team_a_sequence, team_b_sequence) → win prob
- HPC: train many architectures in parallel
- Needs per-game features (DetailedResults works)

### 4. Ensemble/Stacking
- Train 50+ diverse base models across nodes
- Meta-learner (logistic or Bayesian) combines predictions
- HPC: embarrassingly parallel base model training

## Session Decisions

### Phase 1: ESPN Rolling Features (5 → 17 features)
Implemented plan to extend features from 5 Elo-derived to 17 by adding:
- **5 compact-derived features** (always available): `sos_diff`, `win_streak_diff`, `rest_days_diff`, `margin_mean_diff`, `margin_std_diff`
- **7 detail-derived features** (from box scores): `off_eff_r10_diff`, `def_eff_r10_diff`, `efg_pct_r10_diff`, `opp_efg_pct_r10_diff`, `to_rate_r10_diff`, `or_pct_r10_diff`, `pace_r10_diff`

Key design: rolling state tracked per-team via `deque(maxlen=10)` inside the Elo loop. Features extracted BEFORE Elo update (no leakage), state updated AFTER.

Files modified: `features.py`, `transform_espn.py`, `submission.py`, `train.py`, `ml_submit.py`, `backtest.py`, `tune.py`, `ablation.py`

**Backtest results**: Mixed. Men's 2025 XGBoost regressed (0.136 → 0.154), Women's improved (Logistic 0.124 beat Elo 0.136). Likely needs tuning/regularization with the expanded feature set.
